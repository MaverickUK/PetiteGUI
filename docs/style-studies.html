Style studies · the basics only

A desktop for CGA and EGA

Four looks for the same small desktop: a menu bar, two windows, icons, a drop-down menu, an alert and the mouse pointer. Each is drawn at its mode's real resolution and palette, then shown at 4:3 as a CRT would stretch it.

Show

Paper

CGA · mode 06h · 640×200 · 2 colours
  • Black and white, with a 50% dither for grey: the desktop, the scroll track, disabled menu items.
  • A striped title bar marks the active window. Drop shadows and a double-bordered alert add depth without colour.
  • Runs on every CGA, EGA and VGA card. The same 1-bit code would carry over to a Hercules card (720×348).
  • 8×8 text, 80 columns. The font is already in the BIOS ROM.
16,000 bytes a screen · 8 pixels a byte

Arcade

CGA · mode 04h · 320×200 · 4 colours
  • Palette 1, with colour 0 set to blue instead of black. On CGA, colour 0 in this mode can be any of the 16 colours.
  • Solid title bars take the place of Paper's stripes: magenta for the active window, cyan for the rest.
  • 40 columns of 8×8 text, so a window shows about 20 characters: lists suit it better than icon grids, and file sizes drop out where they don't fit.
  • Pixels are nearly square (1.2:1), so icons are easy to draw. It feels more like a game's menus than an office desktop.
16,000 bytes a screen · 4 pixels a byte

Ink

EGA · mode 0Eh · 640×200 · 16 colours
  • Paper's layout and widgets in colour: the same pixel grid, the same 8×8 font and the same widget code, with a different palette table.
  • Works on a 64 KB EGA, the base card. Mode 10h's 16 colours need more memory than that.
  • Colour shows state: a blue title for the active window, yellow folders, grey for disabled items.
64,000 bytes a screen, in four planes

Bevel

EGA · mode 10h · 640×350 · 16 colours
  • Bevels lit from the top left, in white, light grey and dark grey: buttons that look pressable and windows with thick frames.
  • 8×14 text, 25 rows. Pixels are close to square (1.37:1), so detail stays sharp.
  • Needs a 128 KB EGA for 16 colours (a 64 KB card gets 4 in this mode). It also moves 75% more memory than Ink: slow on an 8088, fine on a 286.
112,000 bytes a screen, in four planes

How I'd approach it

The basics, and nothing else yet

  • A desktop with a pattern and a few icons
  • A menu bar with drop-down menus
  • Windows: a title bar, close box and scroll bar; focus, move and close
  • A modal alert with a default button
  • The mouse pointer

Every mockup is built from those parts and a handful of drawing calls, which is also roughly the first milestone's scope.

Build order

  1. Paper first, at 640×200. Every CGA, EGA and VGA card has this mode, and 1-bit drawing is the easiest to make fast on an 8088. Ink then comes nearly free: the same layout, with a palette table and a planar driver.
  2. Byte-aligned windows. Keep window edges on 8-pixel columns (4 in Arcade). Fills, copies and text then work in whole bytes, with no shifting or masking. Every window in these mockups snaps that way.
  3. A small driver per mode. It needs fill rectangle, pattern fill, lines, draw text, and save and restore a rectangle, with one driver each for CGA 1-bit, CGA 2-bit and EGA planar. Widgets call only the driver.
  4. Redraw by rectangles. Draw windows back to front, clipped to the area that changed. A menu saves the pixels under it (Paper's File menu is under 2 KB) and puts them back when it closes.
  5. Let the mouse driver draw the pointer. INT 33h already draws it in modes 04h, 06h, 0Eh and 10h. Hide it (function 2), or hide it only over an area (function 10h), while drawing underneath. Set its shape per mode with function 9: 200-line modes need a squat arrow, as drawn here.
  6. Fonts from ROM to start with. In 200-line modes, use the 8×8 font at F000:FA6E (characters 128–255 come through INT 1Fh). In mode 10h, use the EGA's 8×14 font, found with INT 10h AX=1130h. A proportional font can come later.
  7. C with assembly where it counts. Use Turbo C or Open Watcom in the small or compact model, with the driver's inner loops in assembly.

CGA's two 200-line modes store even lines and odd lines in separate 8 KB banks, so a driver steps through rows in pairs. On a 4:3 screen, a 640×200 pixel is 2.4 times taller than it is wide, which is why the icons, close boxes and pointer are drawn short and wide in Paper and Ink.
